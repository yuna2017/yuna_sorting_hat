# YUNA 分部帽

本项目为燕山大学大学生网络信息协会的协会资产。

燕山大学大学生网络信息协会的部门兴趣分流小游戏。用户完成 12 道行为选择题后，由“分部帽”给出一个建议了解的部门，并可继续查看原因、部门资料、公开招新入口和分享海报。

## 快速开始

```bash
npm install
npm run dev
npm test
npm run check:content
npm run simulate
npm run build
npm run verify
```

本地开发地址默认是：

```text
http://localhost:5173/yuna_sorting_hat/
```

本地视觉检查使用开发依赖 Playwright 和本机已安装的 Microsoft Edge：

```bash
node shoot.mjs
node check-depts.mjs
```

`shoot.mjs` 会验证完整流程、分享海报、复制链接、移动端横向溢出、单一滚动条、减少动态效果和四个部门结果。输出目录 `screenshots/` 已被忽略，不会进入提交。`npm run verify:quality` 是不依赖构建地址的质量检查，`npm run verify` 还会执行本地生产构建，`npm run check:browser` 是完整浏览器验收。

## 用户流程

```text
产生兴趣
  ↓
封面填写昵称
  ↓
开场独白
  ↓
12 道行为选择题
  ↓
分院仪式
  ↓
结果主视觉 + 招新入口
  ↓
为什么是这个部门
  ↓
四部门方向与完整行为画像
  ↓
部门介绍与行动入口
  ↓
分享海报 / 分享链接
```

结果页不是终点，而是招新链路的中间节点。用户至少应该能回答：

1. 我被建议先了解哪个部门？
2. 帽子为什么这样判断？
3. 这个部门实际会做什么？
4. 我现在可以去哪了解或报名？

## 关键约束

- 每场固定抽取 12 道题，不要求技术基础。
- 题池为 12 个槽位，每槽 2 道候选，共 24 道题。
- 每题 4 个选项，各自覆盖四个部门的主推方向；副推方向构成无固定点置换。
- 主推 `+3`，副推 `+1`；部门理论满分为 `12 × 3 = 36`。
- 判定、并列决胜、分享恢复全部确定性执行，不使用随机决胜。
- 随机只用于抽题和选项展示顺序，不能改变选项语义或结果。
- 结果解释只能回读用户自己的选择，不能编造证据。
- 部门结果是“建议了解的方向”，不是能力评定、心理诊断或录取筛选。
- 招新链接、二维码和项目链接只使用协会公共渠道。

## 分享协议

当前版本的结果链接格式：

```text
?v=3&s=<抽题种子 base36>&a=<12 位答案码>
```

- `v`：题库版本，当前为 `3`。
- `s`：抽题种子，用于重建用户当时看到的 12 道题。
- `a`：按抽题顺序记录每题选择的规范选项 ID。

缺少参数、版本不匹配、种子非法或答案长度不符时，链接会被拒绝并回到正常答题流程。修改题目语义、权重、槽位或候选数量时，必须升级题库版本。

## 部署

推送到 `main` 后，`.github/workflows/deploy.yml` 会依次执行：

```text
npm ci → npm test → npm run check:content → npm run build → GitHub Pages 部署
```

当前正式地址为：[https://ysh.yuna.team/](https://ysh.yuna.team/)，使用根路径部署：

```text
VITE_BASE=/
VITE_PUBLIC_PATH=/
VITE_PUBLIC_ORIGIN=https://ysh.yuna.team
```

如果以后重新部署到 GitHub Pages 默认仓库子路径或其他自定义域名，按 [docs/设计文档.md](docs/设计文档.md) 中的环境变量说明调整。

海报图片模式在生产环境需要配置 `VITE_PUBLIC_ORIGIN`。未配置时，生产环境不会显示图片模式，也不会把本地开发地址写进二维码。

## 当前没有显示的占位内容

当前四个部门的事实资料和公开入口均已配置，用户界面不会显示“入口待公布”“成员名单待补充”或“部门介绍仍为草稿”等占位文案。

代码中仍保留的 `contentDraft`、`pending` 和 `null` 分支属于未来维护数据时的防御性校验，不是当前页面内容。未启用的部门微型故事组件和数据已经删除。

## 性能概况

当前构建的 JavaScript gzip 后约 100 KB，CSS gzip 后约 11 KB。主要图片资源约 3.5 MB，应用已改为按流程提前一个阶段加载素材：封面只准备开场资源，开场准备仪式资源，答题阶段准备结果背景，仪式阶段准备胜出部门立绘，结果阶段准备分享海报资源。这样不牺牲流程连续性的同时，避免首屏一次性下载整套图片。

结果海报仍然默认展示。海报生成使用图片缓存和延后绘制，生成完成后有轻量出现动画，不隐藏或削弱海报预览。
