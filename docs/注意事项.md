# 注意事项

## 移动端

- 已完成部分移动端尺寸验证，后续仍需覆盖 Android Chrome、iOS Safari 和微信内置浏览器。
- 检查 320 / 360 / 390 / 412px 下无横向溢出。
- 检查说明卡、底部操作按钮和长分享链接在窄屏下的可用性。
- 地址栏高度差异可能影响 `dvh`，必须进行真机验收。
- 分享图片、下载和剪贴板 API 在微信与 iOS 上可能受限，必须提供手动保存或复制链接降级。

## 内容与外链

- 部门正式资料由社团确认后再写入项目。
- 部门介绍优先链接到社团官网，并提供真实项目或公开作品入口。
- 招新入口只使用公共 URL，不放个人联系方式、内网地址或凭据。
- 招新届次、群号和二维码有时效性，不得永久硬编码为始终开放。
- 入口关闭或待公布时显示明确静态状态，不生成失效链接。

## 题库、判定与分享

- 修改题目后运行 `npm test`；分布模拟完成后还必须运行 `npm run simulate`。
- 部门判定保持零随机，展示顺序随机不得改变规范答案 ID。
- 题库变化可能改变旧分享链接的结果，招新期间不要无计划改题。
- 题库升级应使用版本化分享协议，并保留现有无版本链接的兼容解释。
- 分享卡链接优先指向稳定测试入口或可复现结果，不使用开发、预览或内网地址。
- 海报底部卡片内的招新群号与二维码属于公开入口，换届或群失效时必须同步更新素材和文案。

## 结果表达

- 测试只用于兴趣探索，不用于心理诊断、能力评定或录取筛选。
- “部门结果”表示建议了解的方向，不表示只能加入该部门。
- 行为身份和第二倾向只能用于解释，不得重新改变部门胜者。
- 结果解释必须来自用户实际选择，不随机生成看似个性化的证据。

## 功能边界

- 分部帽不扩展为完整人生模拟器。
- 可增加结果后的部门微型故事，但不加入学期、金币、复杂技能树和长流程存档。
- 微型故事必须可跳过，不得阻断官网、项目或报名入口。
