# 题目

10 道题，每题 4 个选项。配套页面流程见 [页面细节](./页面细节.md)，部门映射见 [设计文档](./设计文档.md)。

### 部门映射

| ID    | 展示名                 | 对应学院 | 关键词         |
| ----- | ------------------- | ---- | ----------- |
| `dev` | 开发部development      | 格兰芬多 | 冒险、领导力、现场应变 |
| `sec` | 网安部cyber security   | 拉文克劳 | 研究、创新、逻辑    |
| `ops` | 运维部operations       | 赫奇帕奇 | 协作、细致、服务精神  |
| `pr`  | 组宣部public relations | 斯莱特林 | 资源整合、影响力、策略 |

## 权重规则

每个选项的权重固定为一种形状：**主推部门 +3，副推部门 +1**。

约束（出题时必须保持，否则结果页会失衡）：

1. 每题的 4 个选项分别主推 4 个不同部门 —— 保证每题对每个部门都提供了一条 +3 的路径。
2. 每题的 4 个「+1 指向」构成**无固定点置换**（不指向自己、且 4 个部门各被指到一次）。
3. 由 1、2 可得：**每个部门的理论满分都是 30 分**（10 题 × 3），最低 0 分。

本文件使用了 3 种置换模式循环：

| 模式 | +1 指向 |
| --- | --- |
| P1 | dev→sec, sec→ops, ops→pr, pr→dev |
| P2 | dev→ops, sec→pr, ops→dev, pr→sec |
| P3 | dev→pr, sec→dev, ops→sec, pr→ops |

## 判定规则

**归一化**：雷达图与百分比一律用 `score / 30`，不要用 `score / 总分`——后者会让四个轴互相挤压，看不出个人特征。

**最终部门**：取最高分。并列时依次判定：

1. 比较该部门被**主选**（吃到 +3）的次数，多者胜；
2. 仍并列 → 取 Q10 所选的主推部门，若它在并列集合中则它胜（Q10 是价值观题，适合当决胜局）；
3. 仍并列 → 按固定顺序 `dev > sec > ops > pr` 取第一个。**不要用随机**，否则同一份答案刷新会得到不同结果，分享链接也无法复现。

## 出题备注

- **选项顺序**：本文件里各部门出现的位置已经打散，避免「答案永远在 A」。建议渲染时再按**固定种子**打乱一次（种子可用 session id），既防套路又保证同一次答题里顺序不跳。
- **文案长度**：选项都控制在一行内，为移动端和打字机效果留余量。
- **不需要任何技术知识**：全部是行为倾向题，大一新生零基础也能答——这是硬要求，别加「你更喜欢哪种协议」这类题。
- **帽子低语**：对应 [页面细节](./页面细节.md) 里「分部帽的评论」。可全用，也可随机抽 3～4 题显示，避免节奏拖沓。
- **想加题**：保持每题「4 选项 / 各主推一个部门 / +1 构成无固定点置换」即可，满分会自动变成 `题数 × 3`，判定和归一化逻辑都不用改。
