# 《燕山大学人生模拟器》参考审阅

## 1. 审阅范围

参考项目位于：

```text
E:/items/nether/yuna/simulator
```

审阅覆盖整体设计、事件系统、页面状态机、游戏引擎、存档、事件/技能/职业数据、毕业报告、分享海报、内容转换与数值模拟脚本。

截至 2026 年 8 月 26 日，参考项目代码中包含 73 个事件，其中 67 个常规事件、6 个隐藏事件；一局按 8 学期、每学期 3 个事件推进，共 24 个事件。

## 2. 值得借鉴的能力

### 校园世界而不只是校园文案

宿舍、食堂、图书馆、教学楼、社团街、操场、世纪楼、大活、校园、隐藏地点和 YUNA 工坊共同构成可探索空间。场景、学期窗口和校区替换文本让内容更接近真实燕大生活。

### 内容数据化

事件题面、选项、属性、技能、伙伴、金币、结果反馈和解锁条件都由数据驱动，界面不直接维护具体事件。

### 选择—成长—身份闭环

玩家的选择改变属性、技能和关系，并最终形成“数字造物者”“系统守夜人”“安全哨兵”“校园叙述者”等隐藏身份。身份由过程积累产生，而不是一次答题直接贴标签。

### 数值模拟

`npm run simulate` 批量模拟不同玩法，检查评级分布、职业可达性、技能供给、幸运的实际影响和文科/技术玩法差异。这种整体分布体检比只写单元测试更适合内容型游戏。

### 内容生产与传播

事件库可以在策划文档与 JavaScript 数据之间导入、导出；毕业报告包含指数、身份、技能和行为统计，YUNA 介绍被放在体验完成之后，以“继续探索”而不是强制广告的方式进入。

## 3. 不直接照搬的部分

分部帽不需要：

- 8 学期与 24 回合流程
- 金币、伙伴和复杂属性成长
- 完整技能树和长流程存档
- 大规模随机事件池
- 将招新入口藏到完整游戏结束之后

分部帽的核心优势是短、明确、可复现。扩展必须服务“理解结果和进入招新”，不能牺牲完成率。

## 4. 对分部帽的直接转化

| 模拟器能力 | 分部帽对应方案 |
| --- | --- |
| 隐藏身份 | 结果页行为身份，但不改变部门判定 |
| 事件系统 | 每部门 2～3 个结果后微型故事 |
| 数值模拟 | 四部门胜率、并列率和策略分布脚本 |
| 内容导入导出 | 先做内容完整性校验，再评估生成流程 |
| 毕业海报 | 部门结果分享卡与可复现二维码 |
| YUNA 工坊 | 代表项目、官网和公共报名入口 |
| 存档版本 | 分享协议和题库版本管理 |

## 5. 参考项目暴露的风险

- 文档中的“待合入”状态可能与代码实际事件数量不一致
- 大量 `Math.random()` 使某一局难以复现；长流程游戏更适合带种子的随机
- 存档只检查少数字段时，损坏数据可能导致运行时错误
- 文档声称支持浏览器回退，但单页状态机未必真正支持撤销
- 招新届次、群号和链接硬编码会随时间过期
- 固定测试入口二维码只能引流，不能恢复分享者的同一结果

分部帽当前的零随机判定和答案分享码应继续保留，并通过版本化提高长期兼容性。

## 6. 决策

1. 不把分部帽改造成完整人生模拟器。
2. 优先完成正式部门资料、代表项目和公共招新入口。
3. 增加题库分布模拟与内容完整性校验。
4. 分享卡复用现有答案编码，并规划题库版本字段。
5. 行为身份和微型故事列为结果后的可选增强，不参与原判定。
6. 所有新增内容继续数据化，并为相同输入提供确定性结果。
