# 页面与交互

## 流程

```text
封面 → 开场 → 答题 → 分院仪式 → 结果
```

结果页之后的目标链路：

```text
结果 → 了解部门 → 社团官网 / 招新入口 → 分享
```

## 页面状态

### 封面 `[x]`

- 夜空背景使用 CSS 实现。
- 展示协会名称、分部帽标题、YUNA SORTING HAT 和招新季信息。

### 开场 `[x]`

- 分院帽独白使用打字机效果。
- 点击可跳过；用户开启减少动态效果时直接显示全文。
- 读屏使用完整文本，不逐字播报动画过程。

### 答题 `[x]`

- 共 10 题，每题 4 个选项。
- 选项顺序按会话种子打乱，同一场答题内保持稳定。
- 选中后显示选项说明卡，用户可以改选和回退。
- 使用固定的“下一题”按钮推进，不自动跳题。
- 选中态和说明卡使用中性金色，不提前暴露部门颜色。

### 分院仪式 `[x]`

- 位于答题与结果之间。
- 展示帽子、候选部门、犹豫文案和最终揭晓。
- 点击“跳过”或整屏可直接进入结果。
- 仪式不参与判定，减少动态效果时缩短流程。

### 结果 `[x]`

展示顺序：

1. 你的部门
2. 帽子为什么这么判
3. 关键词
4. 四部门契合度
5. 部门简介或官网入口
6. 招新入口
7. 分享结果
8. 再测一次

雷达图负责展示整体形状，分数条负责展示精确数值。结果页应保留“仅用于娱乐与自我探索”的说明。

部门正式介绍将由社团提供，并优先通过社团官网链接引导；当前代码中的部门内容仍需核对。

### 分享卡 `[ ]`

分享卡需要包含：

- 部门名称和立绘
- 结果文案或关键词
- 测试入口
- 招新二维码
- 与部门主题一致的视觉样式

雷达图可以作为辅助视觉。分享卡设计中突出并标注 50 分参考线，让用户更容易判断各部门兴趣倾向；它是阅读辅助，不改变判定规则。

当前已完成：

- 系统分享
- 通过 `?a=<10位码>` 恢复结果

## 移动端验收

已验证部分移动端尺寸可以正常使用。后续继续检查：

- 320 / 360 / 390 / 412px 是否无横向溢出
- 说明卡展开后是否仍易读
- 底部操作按钮是否始终可用
- 长分享链接是否不会撑破布局
- Android Chrome、iOS Safari、微信内置浏览器的地址栏和 `dvh` 表现
