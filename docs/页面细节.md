# 页面与交互

## 流程

```text
封面 → 开场 → 答题 → 分院仪式 → 结果
```

结果页之后的目标链路：

```text
结果 → 了解部门 → 代表项目 / 社团官网 / 招新入口 → 分享
```

可选扩展：

```text
结果 → 你的第一个部门任务 → 代表项目 / 社团官网 / 招新入口
```

微型任务只增强代入感，不改变原测试结果，也不阻断用户直接报名或离开。

## 页面状态

### 封面 `[x]`

- 夜空背景使用 CSS 实现。
- 展示协会名称、分部帽标题、YUNA SORTING HAT 和招新季信息。
- 招新季文案如包含届次，应集中配置，避免长期显示过期信息。

### 开场 `[x]`

- 分院帽独白使用打字机效果。
- 点击可跳过；用户开启减少动态效果时直接显示全文。
- 读屏使用完整文本，不逐字播报动画过程。

### 答题 `[x]`

- 共 10 题，每题 4 个选项。
- 选项顺序按会话种子打乱，同一场答题内保持稳定。
- 选中后显示选项说明卡，用户可以改选和回退。
- 使用固定的“下一题”按钮推进，不自动跳题。
- 选中态和说明卡使用中性金色，不提前暴露部门颜色。
- 展示顺序随机只影响位置，不改变规范选项 ID、权重和分享码。

### 分院仪式 `[x]`

- 位于答题与结果之间。
- 展示帽子、候选部门、犹豫文案和最终揭晓。
- 点击“跳过”或整屏可直接进入结果。
- 仪式不参与判定，减少动态效果时缩短流程。

### 结果 `[x]`

当前展示顺序：

1. 你的部门
2. 帽子为什么这么判
3. 关键词
4. 四部门契合度
5. 部门简介或官网入口
6. 代表项目与招新入口
7. 分享结果
8. 再测一次

雷达图负责展示整体形状，分数条负责展示精确数值。结果页应保留“仅用于娱乐与自我探索”的说明。

部门正式介绍由社团提供，并优先通过社团官网链接引导；代码中的部门内容在 `contentDraft` 清除前都视为待核对草稿。

计划增加但不改变判定的结果层：

- 行为身份：用固定规则概括用户选择方式
- 第二高契合方向：提醒用户兴趣可能是复合的
- 代表项目：用真实作品说明部门工作

### 部门微型故事 `[ ]`

- 每个部门 2～3 个真实工作场景。
- 每个场景包含题面、选项和选后反馈。
- 场景数据独立于组件维护。
- 从结果页进入，可随时跳过。
- 不重新计分、不改变部门、不改变分享码。
- 总新增体验控制在 1～2 分钟。

| 部门 | 示例场景 |
| --- | --- |
| 开发部 | 临时制作招新页面、修复线上功能 |
| 网络安全部 | CTF 题目分析、安全事件复盘 |
| 运维部 | 活动前服务故障、部署与监控 |
| 组宣部 | 活动传播、海报与内容记录 |

### 分享卡 `[ ]`

分享卡需要包含：

- 部门名称和立绘
- 结果文案或行为身份
- 四部门契合度辅助视觉
- 测试入口或可复现结果二维码
- 可选的公共招新入口
- 与部门主题一致的视觉样式

雷达图可突出并标注 50 分参考线；它是阅读辅助，不改变判定规则。

二维码优先级：

1. 当前可复现结果链接，或稳定测试入口
2. 经确认的协会公共招新入口
3. 不允许开发地址、内网地址和个人邀请链接

当前已完成：分享链接、复制、系统分享和 `?v=1&a=<10位码>` 恢复结果。

尚未完成：分享协议版本化、分享卡 UI、二维码、保存或复制图片。

### 行动入口 `[~]`

结果页行动应分为：

1. 了解部门
2. 查看代表项目
3. 加入招新 / 报名

入口支持开放、关闭和待公布状态。不可用时显示状态说明，不渲染 404 或过期链接。

## 移动端验收

- 320 / 360 / 390 / 412px 无横向溢出
- 说明卡展开后仍易读
- 底部操作按钮始终可用
- 长分享链接不会撑破布局
- 分享卡预览和保存可操作
- Android Chrome、iOS Safari、微信内置浏览器的地址栏和 `dvh` 表现正常
