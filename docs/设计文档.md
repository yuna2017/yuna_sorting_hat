# 分部帽小游戏

参考项目：[燕山大学人工智能学院简易模拟器](https://www.misakacloud.net/games/ysu-emulator/)

> 实现进度与待办见 [TODO](./TODO.md)。代码结构与开发命令见仓库根目录 README。

## 项目定位

### 玩法形式

10 道左右选择题，每个选项对应不同部门的权重（开发部 +3、运维部 +1……）。

实际采用固定形状：**主推部门 +3，副推部门 +1**，每题四个选项各主推一个不同部门，
四个副推构成无固定点置换。因此每个部门理论满分 = 题数 × 3 = 30。
详见 [题目](./题目.md)。

## 架构

### 实现

原计划：参考大海的 react + Tailwind CSS + vite，部署可用 github pages 或者 cf。

实际栈：**React 19 + TypeScript + Tailwind v4（CSS-first）+ Vite 8**，
测试用 vitest。部署走 **GitHub Pages + Actions**，`base` 为 `/yuna_sorting_hat/`；
设环境变量 `VITE_BASE` 可改成 CF 的根路径。

**不引路由** —— 四屏是线性流程，顶层状态机足够；GH Pages 是纯静态无 rewrite，
`BrowserRouter` 的深链与刷新会 404。分享链接用 `?a=` 查询参数即可。

### 功能

分享（带招新二维码）。

本轮**只留接缝、未做 UI**：`src/lib/shareCode.ts` 已实现答案 ⇄ URL 编解码，
访问 `?a=<10位码>` 可完整复现某份结果与雷达图。分享卡与二维码留到下一轮。

## 实现期定下的几个决策

记在这里，免得后来的人重新纠结一遍。

### 部门主题色跟随立绘，不用霍格沃兹院色

四张立绘各带鲜明主色：dev 宝蓝、sec 青×黑、ops 琥珀金、pr 樱粉。
与被指定的院色只有 sec（拉文克劳蓝）、ops（赫奇帕奇黄）对得上 ——
dev 是格兰芬多红金但立绘是蓝的，pr 是斯莱特林绿但立绘是粉的。
**以立绘为准**，院名只作文字点缀。

配色实现为 `[data-dept]` + CSS 变量，结果页根节点翻一个属性就整体换肤，
零 JS 配色逻辑，将来的分享卡直接复用。

### 结果页图表用「一个主角」形式

四部门契合度用雷达图给形状 + 下方四项读数给精确数字，两者不重复标注。
冠军用部门强调色，其余三项淡化 —— 本页的叙事是「你是某个部门」，
一个是主角、其余是背景。副作用是四个部门色**永不同屏**，
所以不受分类调色板的相邻区分度约束。四色在夜底上均达 WCAG AA。

### 不引 Google Fonts（重要）

`fonts.googleapis.com` **在中国大陆不可达**，而受众正是国内高校新生。
render-blocking 的外链样式表会把首屏拖到超时，最坏情况白屏。
两条字栈都只用系统字。

将来换字体请**自托管 woff2 打进产物**，不要用 CDN 外链；
`--font-display` 里已把 `'Cinzel'` 放在首位，丢进字体文件即自动生效。

### 标题衬线、正文黑体

两条字栈分工明确，改版式时别混用：

| token | 用在哪 | 为什么 |
| --- | --- | --- |
| `--font-display`（衬线） | 拉丁小标、院名、编号，封面「分部帽」、结果页部门名 | 只在**大字号、看一眼**的地方；魔法感靠它 |
| `--font-body`（黑体） | 题面、选项、开场独白、结果正文 —— 一切要读的字 | 宋体横细竖粗，小字号在屏幕上发虚 |

配套两条，都是为了同一件事（正文别发虚）：

- `body` 上**刻意不写** `-webkit-font-smoothing: antialiased` ——
  它在 macOS 上会减轻字重，而本站是浅字压深底，最吃这个亏。
- 中文一律**不用 `italic`** —— 中文没有真正的斜体，浏览器只能伪斜（合成倾斜），
  笔画被拉歪、更显细。语气交给「」引号与金色。

### 答题页的视觉层级：场景是配角

一屏的注意力顺序必须是**标题 → 选项**，场景描述垫在中间做氛围，不抢戏。

场景句（如「开学第一天，你把行李扔在床上，插上网线——不通。」）写得挺抓人，
早期版本还给它加了一条金色左边线 —— 但深底上的金色 = 「重点框」信号，
结果注意力被吸在描述上，反而不细看选项。所以场景**不带任何强调装饰**。

弱化的手段是**字号与字重的对比**，不是继续调暗：
调暗会伤对比度，而它毕竟是要读的句子，字色仍需保持 `parchment-dim` 这一档
（夜底上约 8.7:1）。同理，选项的字号与字色都刻意压过场景，让视线自然落上去。

### 选项洗牌只影响显示

选项按会话种子打乱渲染顺序（防「答案永远在 A」），但答案一律记规范 option id。
于是种子与计分、与分享链接完全解耦 —— 分享码只需带答案，不必带种子。

### 判定全程零随机

并列决胜依次走「主选次数 → 决胜题 → 固定顺序 dev > sec > ops > pr」。
穷举全部 4^10 = 1,048,576 种答案组合实测：顶部并列占 6.86%，
其中 1.22% 会一路落到固定顺序回退。四部门冠军分布 25.31 / 25.00 / 25.00 / 24.69%，
基本均衡。
