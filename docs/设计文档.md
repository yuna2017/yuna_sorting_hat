# YUNA 分部帽设计说明

## 1. 项目定位

面向协会招新的互动小游戏。用户通过 10 道选择题了解可能适合的部门，再进入部门官网、招新入口或分享结果。

核心链路：

```text
产生兴趣 → 完成测试 → 获得结果 → 理解原因 → 了解部门 → 报名 / 分享
```

测试结果是招新链路的中间节点，不是终点。

## 2. 玩法与判定

- 10 道行为倾向题，不要求技术基础。
- 每题 4 个选项。
- 每个选项：主推一个部门 `+3`，副推一个部门 `+1`。
- 每题 4 个选项分别主推四个部门，副推构成无固定点置换。
- 当前每个部门满分为 `10 × 3 = 30`。
- 并列决胜使用固定规则，不使用随机数。
- 选项洗牌只改变显示顺序，不改变答案 ID、计分或分享结果。

权威题目和权重规则见 [题目](./题目.md)。

## 3. 页面结构

```text
cover → opening → quiz → reveal → result
```

顶层使用状态机，不引入路由。分享结果通过查询参数 `?a=` 恢复，适合 GitHub Pages 的纯静态部署。

## 4. 技术约束

- React + TypeScript + Vite + Tailwind CSS
- Vitest 负责题库、计分、解释和分享码测试
- GitHub Actions 发布 GitHub Pages
- 不使用 Google Fonts；字体使用系统字栈或未来自托管的 woff2
- 不为线性流程引入额外路由或复杂状态管理

## 5. 视觉与交互决策

### 部门主题色

主题色跟随部门立绘，不使用霍格沃兹学院色。学院名称只作为文案点缀。

结果页通过 `[data-dept]` 和 CSS 变量换肤。

### 结果页层级

结果页遵循：

```text
先讲故事 → 解释结果 → 展示数据 → 介绍部门 → 引导行动 → 分享
```

冠军部门是视觉主角，其他部门在雷达图和分数条中弱化。

### 雷达图

当前雷达图展示 4 个部门的契合度形状，精确数值由分数条展示。

分享卡阶段可突出并标注 50 分辅助参考线，便于用户判断兴趣倾向。参考线仅用于阅读，不参与计算。

### 动态效果

动态效果服务于分院仪式和阅读节奏，不得影响判定、分享结果或减少动态效果用户的可用性。

## 6. 部门内容策略

正式资料加入前，代码中的部门内容视为待核对草稿。

正式版本应：

- 使用协会确认的部门事实
- 优先链接到社团官网的部门介绍页
- 使用协会公共招新或报名入口
- 不放个人联系方式、内网地址或凭据
- 避免空泛宣传语，优先说明“部门做什么”和“新生会接触什么”

数据入口：`src/data/departments.ts`。
