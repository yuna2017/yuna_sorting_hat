# YUNA 分部帽产品与技术说明

> 版本：v3
>
> 审计日期：2026 年 9 月 4 日
>
> 本文合并原设计、页面细节和注意事项，描述当前已经实现的版本，不记录已经取消的实验方案。

## 1. 产品定位

YUNA 分部帽是燕山大学大学生网络信息协会的招新兴趣分流小游戏。本项目为协会资产。它通过 12 道无技术门槛的行为题，帮助新生先了解一个可能感兴趣的部门，再进入部门资料、公开招新入口或分享流程。

核心链路：

```text
产生兴趣 → 完成测试 → 获得结果 → 理解原因 → 了解部门 → 报名 / 分享
```

它不是心理测评，不用于能力评定、录取筛选或诊断。结果表示“建议优先了解的方向”，用户始终可以选择其他部门。

项目不扩展为完整校园人生模拟器，不引入学期、金币、复杂技能树、长流程存档或与招新无关的系统。

## 2. 当前流程和状态机

```text
cover → opening → quiz → reveal → result
```

状态机位于 `src/App.tsx`，当前不使用路由。

| 阶段 | 用户看到的内容 | 关键行为 |
| --- | --- | --- |
| `cover` | 协会名称、分部帽、昵称输入 | 开始测试；昵称只用于本地结果和海报 |
| `opening` | 分部帽独白 | 打字机显示；支持跳过和减少动态效果 |
| `quiz` | 12 道题，每题 4 个选项 | 可回退、改选；选中后显示低语与点评 |
| `reveal` | 分院帽仪式 | 只延迟揭晓，不参与判定；可跳过 |
| `result` | 结果、解释、数据、部门资料、分享 | 连续滚动；分享链接可直达 |

分院仪式和结果解释都不改变 `resolveWinner()` 的结果。相同答案在刷新、跳过仪式、减少动态效果和分享恢复后必须一致。

## 3. 结果页当前结构

结果页采用移动端竖屏优先的连续滚动布局，页面只有浏览器主滚动条，不能再增加内部滚动容器。

```text
1. 结果主视觉 + 加入招新 / 了解部门
2. 帽子在你身上看见了什么
3. 四部门方向：雷达图默认展示
4. 契合度柱状图：默认收起
5. 完整行为画像：默认展开
6. 关于这个部门
7. 行动入口
8. 探索其他部门
9. 分享结果：图片模式默认展示
10. 再测一次与页脚
```

### 3.1 结果主视觉

- 部门立绘、部门名、拉丁名、slogan 和事实定位组成首屏。
- 主按钮优先使用公共招新入口。
- 次按钮跳到部门介绍。
- 关键词和霍格沃兹学院信息只作为氛围点缀，不盖过部门结论。

### 3.2 结果解释

- 解释文案由部门胜出强度决定。
- 行为身份由 `src/lib/identity.ts` 根据答案、主副推次数和证据固定生成。
- 证据只取用户实际选择过的选项，当前默认最多展示 3 条。
- 并列信息只说明帽子曾经犹豫，不重新判定结果。

### 3.3 数据展示

- 雷达图用于展示四部门方向的整体形状。
- 契合度柱状图默认收起，用户主动查看时再显示精确分数。
- 五特质行为画像默认展开，优先让用户理解“自己倾向怎样做事”。
- 数据只用于娱乐和自我探索，不评价能力高低。

### 3.4 分享海报

- 图片模式默认展示，不再要求用户先打开弹窗。
- 海报预览、昵称输入、系统分享、保存图片和长按保存提示均保留。
- 海报包含部门、立绘、行为身份、辅助数据和公共招新二维码。
- 海报二维码不能使用 localhost、内网地址、临时预览地址或私人联系方式。

## 4. 动效策略

动效只能服务于揭晓、阅读和结果理解，不能影响判定和可用性。

- 背景粒子：固定在视口，使用低成本的 transform / opacity 漂移和呼吸，不制造额外页面高度。
- 结果立绘：缓慢浮动。
- 雷达图：第一次进入视口时播放完整展开和数据点依次出现；离开后再次进入时使用快速重播。
- 契合度和特质柱状图：第一次进入时从 0 增长到目标值；再次进入时快速重播。
- `prefers-reduced-motion: reduce` 时直接呈现最终结果，不等待动画。

### 4.1 资源加载策略

应用不在启动时预加载全部图片，而是提前一个页面阶段准备下一段流程所需素材：

```text
cover  → opening 所需分部帽素材
opening → reveal 所需帽子、魔法阵素材
quiz   → result 背景素材
reveal → 结果背景 + 胜出部门立绘
result → 分享海报所需 logo、二维码素材
```

预加载资源使用低优先级，避免抢占当前页面。当前页面实际使用的图片仍由组件正常加载，预加载只负责让下一阶段更平滑。

图表组件通过 `IntersectionObserver` 判断进入视口，并记录当前组件的播放次数。首次播放和重复播放使用不同 CSS 状态。

## 5. 技术架构

```text
React + TypeScript + Vite
        │
        ├─ App.tsx：状态机、题目会话、分享直达
        ├─ screens：封面、开场、答题、仪式、结果
        ├─ components：按钮、图表、部门卡、分享和海报面板
        ├─ data：题池、部门、特质、活动配置
        └─ lib：抽题、计分、解释、画像、分享、海报、校验
```

工程原则：

- 运行时内容数据与展示组件分离。
- 计分、解释、分享和海报绘制使用纯函数或确定性流程。
- 不为当前线性流程引入额外路由或复杂状态管理。
- CSS 不依赖 Google Fonts；字体使用系统栈，避免国内首屏阻塞。
- 任何新增功能不能阻断“理解结果 → 进入招新”的核心链路。

## 6. 部门资料和行动入口

部门数据位于 `src/data/departments.ts`，活动和公共招新配置位于 `src/data/campaign.ts`。

每个部门必须提供：

- `tagline`：事实定位；
- `intro`：部门实际职责；
- `doing`：新成员会接触的 2～4 件事情；
- `suitedFor`：帮助新生自我判断的描述；
- `actions`：了解部门、文章 / 作品、公共招新入口。

行动入口只使用公开的协会官网、文章、报名页或招新群。入口关闭或缺失时，代码保留静态降级逻辑；当前四个部门的正式入口均已配置。

## 7. 分享与部署

分享链接：

```text
?v=3&s=<抽题种子 base36>&a=<12 位答案码>
```

当前协议只接受与 `QUESTION_POOL.version` 相同的版本。旧版本和缺少种子的链接会被拒绝，避免新题库误读旧答案。

部署变量：

| 变量 | 用途 | 当前正式部署值 |
| --- | --- | --- |
| `VITE_BASE` | Vite 资源根路径 | `/` |
| `VITE_PUBLIC_PATH` | 海报二维码中的站点路径 | `/` |
| `VITE_PUBLIC_ORIGIN` | 海报二维码的公开域名，不含路径 | `https://ysh.yuna.team` |

GitHub Actions 会执行测试、内容检查和构建后再部署。当前正式地址为 [https://ysh.yuna.team/](https://ysh.yuna.team/)，使用根路径配置；线上二维码和外链仍需定期检查。

## 8. 质量与完成度

已实现的自动化检查：

- 题库结构、选项覆盖、特质预算、槽位和决胜槽校验；
- 计分、并列决胜、解释、行为身份和分享协议单测；
- 四部门胜率、平均分和并列率分布模拟；
- 部门资料字段、公开 URL 和行动类型检查；
- Playwright 全流程、四部门直达、海报生成、移动端宽度和滚动容器检查；
- `tsc -b` 与 Vite 生产构建。

当前已知的非阻塞事项：

1. 真实线上域名和二维码需要在发布环境确认；
2. 浏览器模拟不能替代真实 iOS Safari、Android Chrome 和微信内置浏览器；
3. 外链目前主要做格式和渲染检查，尚未建立定期 HTTP 可达性监控；
4. 尚未接入匿名招新转化统计、自动可访问性审计和性能预算；
5. 题库和招新活动信息需要随届次更新，并严格维护版本记录。

## 10. 后续优化建议

按收益和风险排序：

### P0：发布可信度

- 为 `VITE_PUBLIC_ORIGIN` 配置正式域名并生成一次真实二维码；
- 在真实手机上验证海报长按保存、系统分享、剪贴板降级和地址栏变化；
- 为公共招新链接增加周期性可达性检查；
- 建立 `release-notes`，记录题库版本、活动届次、二维码和入口变更。

### P1：质量和可访问性

- 增加键盘焦点、读屏顺序、颜色对比度和动态偏好审计；
- 为图表补充更清晰的文本摘要，确保不依赖视觉读取；
- 对首屏图片、背景图和海报生成建立体积预算；
- 将 `shoot.mjs` 纳入可重复的发布验收，而不是只在本地手动执行。

### P2：招新效果

- 在不收集个人身份的前提下统计结果页到招新入口的匿名点击率；
- 对首屏主按钮、部门介绍按钮和分享按钮做小范围文案比较；
- 根据真实反馈调整部门简介长度和入口顺序；
- 观察用户是否会主动展开契合度分数和行为画像，决定是否继续保留完整数据。

### P3：内容迭代

- 仅在部门愿意维护并核对内容时，重新评估部门微型任务；
- 代表项目、比赛复盘和活动作品优先使用稳定的协会公开页面；
- 题库改动必须先做分布模拟，再决定是否升级版本。
