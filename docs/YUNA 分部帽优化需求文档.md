# YUNA 分部帽后续规划

## 目标

在现有测试流程上补齐四个环节：

1. 正式、可信的部门内容
2. 结果解释和行为身份
3. 部门了解与招新转化
4. 可复现的结果分享与传播

目标流程：

```text
测试 → 分院仪式 → 部门结果 → 为什么是你 → 了解部门
     → 项目 / 官网 / 报名 → 分享
```

可选增强：

```text
部门结果 → 你的第一个部门任务 → 项目 / 官网 / 报名
```

## 参考项目审阅结论

《燕山大学人生模拟器》已经形成“校园场景 → 事件选择 → 属性与技能成长 → 隐藏身份 → 毕业报告 → YUNA 工坊”的完整系统。分部帽应学习它的内容数据化、数值模拟、身份叙事、海报传播和软性转化，不复制其学期、金币、复杂技能树和 24 回合内容规模。

- 人生模拟器负责校园人生体验和 YUNA 品牌认知
- 分部帽负责部门方向探索和招新分流
- 分部帽必须继续保持短流程、零随机判定和结果可复现

详细审阅见 [燕大人生模拟器参考审阅](./燕大人生模拟器参考审阅.md)。

## 当前工作顺序

### P0：上线可信度

- 收集并核对四个部门的正式资料
- 为每个部门确定社团官网、代表项目和公共报名入口
- 清除过期届次、群号和招新链接；入口关闭时提供明确降级状态
- 完成 GitHub Pages 发布确认
- 完成 Android Chrome、iOS Safari、微信内置浏览器验收
- 招新期冻结题库并记录当前题库版本

### P1：分享、兼容与工程体检

- 实现结果分享卡和保存图片
- 分享卡使用部门主题、立绘、结果文案和可复现链接
- 二维码优先指向测试入口或当前结果链接；公共招新入口作为第二行动
- 雷达图突出并标注 50 分辅助参考线
- 给分享协议加入版本号并兼容现有无版本链接
- 增加题库分布模拟脚本
- 增加部门文案和外链完整性校验
- 在 CI 中运行单元测试、内容校验和生产构建

### P2：结果叙事与轻量内容扩展

- 在现有证据解释上增加固定规则生成的行为身份
- 呈现第二高契合方向，但避免制造“唯一正确部门”的错觉
- 为每个部门设计 2～3 个结果后微型场景
- 微型场景只增强理解和代入感，不重新判定部门
- 决定真实项目展示由结果页承载，还是统一跳转社团官网
- 评估匿名、最小化的访问与招新转化统计

### P3：体验增强

- 替换最终分院帽素材
- 增加结果页和雷达图动效
- 评估音效
- 优化分享图片生成和图片资源体积

## 行为身份要求

行为身份是结果解释层，不是第二套测评。它必须满足：

- 部门胜者仍唯一来自 `resolveWinner()`
- 身份来自实际答案、主副推次数和证据选项
- 相同答案始终得到相同身份
- 不使用医学、心理学或能力评定措辞
- 明确“适合了解”不等于“只能加入”

候选名称可以借鉴人生模拟器的表达方式，如“数字造物者”“系统守夜人”“安全哨兵”“校园叙述者”，但最终命名与部门事实须由协会核对。

## 部门微型故事要求

- 每个部门 2～3 个场景，总新增体验控制在 1～2 分钟
- 场景来自真实工作：开发项目、CTF 复盘、服务故障、活动传播等
- 用户可以跳过并直接查看官网或报名
- 选项只改变场景反馈，不改变原测试结果
- 不引入复杂存档、金币、学期或技能树
- 内容继续数据化，不写死在 React 组件中

## 内容要求

- 部门事实必须由社团确认
- 介绍优先说明部门职责、实际工作和适合人群
- 正式介绍优先使用社团官网链接
- 招新链接必须是协会公共渠道，并配置开放/关闭状态
- 代表项目、文章、比赛复盘或活动作品优先于宣传口号
- 文档、题库、代码和分享协议必须记录版本关系

## 验收标准

### 核心流程

- [ ] 测试流程无明显卡顿
- [x] 分院仪式可展示、可跳过、可减少动态效果
- [x] 当前分享链接恢复结果后判定一致
- [ ] 可以从结果进入部门官网、代表项目和招新入口
- [ ] 结果明确说明测试仅用于兴趣探索

### 分享

- [x] 可复制结果链接
- [x] 支持系统分享的设备可调用系统分享
- [ ] 分享卡展示部门结果、行为身份或结果文案、测试入口
- [ ] 分享卡二维码指向公开、稳定、可访问的地址
- [ ] 保存图片与复制图片在主流移动浏览器有可用降级
- [ ] 旧分享链接在题库升级后仍能按对应版本解释

### 题库与工程

- [x] 题库结构有自动校验
- [x] 计分和分享码有测试
- [ ] 有题库分布模拟报告
- [ ] 有部门文案、占位状态和外链完整性检查
- [ ] CI 依次执行测试、内容检查和构建
- [ ] 修改题目前记录题库版本并评估旧链接影响

## 不做的事情

- 不把分部帽扩展为完整人生模拟器
- 不引入学期、金币、复杂技能树和长流程存档
- 不进行无目标的技术栈重构
- 不引入 Google Fonts
- 不为当前线性流程引入路由
- 不在资料未确认前编造部门事实
- 不在招新期间无计划修改题库
- 不为了结果“更有趣”而在判定中加入随机数
