# YUNA 分部帽后续规划

## 目标

在现有测试流程上补齐三个环节：

1. 结果解释
2. 部门了解与招新
3. 结果分享与传播

最终流程：

```text
测试 → 分院仪式 → 结果 → 了解部门 → 社团官网 / 招新 → 分享
```

## 当前已完成

- 封面、开场、答题、分院仪式、结果页
- 结果解释、雷达图、分数条、并列提示
- 四部门立绘、主题色和基本数据结构
- 分享链接、复制和系统分享
- 题库校验、计分测试、构建与部署配置

## 当前工作顺序

### P0：上线准备

- 收集并核对四个部门的正式资料
- 为每个部门确定社团官网介绍链接
- 确定公共招新 / 报名链接
- 完成 GitHub Pages 发布确认
- 完成 Android、iOS、微信内的移动端验收

### P1：分享与转化

- 实现结果分享卡
- 加入招新二维码
- 分享卡使用部门主题和立绘
- 雷达图突出并标注 50 分辅助参考线
- 结果页通过官网链接引导用户了解部门
- 确认项目展示由结果页承载，还是统一跳转社团官网

### P2：体验增强

- 替换最终分院帽素材
- 增加结果页和雷达图动效
- 评估音效
- 优化分享图片生成
- 增加匿名、最小化的访问与招新转化统计
- 优化图片资源体积

## 内容要求

- 部门事实必须由社团确认。
- 介绍优先说明部门职责、实际工作和适合人群。
- 正式介绍优先使用社团官网链接，避免在测试页维护重复长文案。
- 招新链接必须是协会公共渠道。

## 验收标准

### 核心流程

- [ ] 测试流程无明显卡顿
- [x] 分院仪式可展示、可跳过、可减少动态效果
- [x] 分享链接恢复结果后判定一致
- [ ] 可以从结果进入部门官网和招新入口

### 分享

- [x] 可复制结果链接
- [x] 支持系统分享的设备可调用系统分享
- [ ] 分享卡能展示部门结果和测试入口
- [ ] 二维码指向确认后的公共招新 URL
- [ ] 分享卡中的雷达图具有 50 分辅助参考线

### 移动端

- [~] 部分尺寸已验证正常
- [ ] 320 / 360 / 390 / 412px 无横向溢出
- [ ] Android Chrome 正常
- [ ] iOS Safari 正常
- [ ] 微信内置浏览器正常

### 题库与工程

- [x] 题库结构有自动校验
- [x] 计分和分享码有测试
- [ ] 修改题目后必须重新运行测试并确认旧分享链接影响

## 不做的事情

- 不进行技术栈重构。
- 不引入 Google Fonts。
- 不为线性流程引入路由。
- 不在资料未确认前编造部门事实。
- 不在招新期间无计划修改题库。
